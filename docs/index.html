What it does

The gap this fills, in plain terms.

Enterprise customers who want Claude connected to their own business systems need someone to build that connector. This server is that connector for HubSpot: it speaks the Model Context Protocol, a standard that lets Claude call out to external tools, and translates each call into a real, authenticated HubSpot API request.

Ask Claude to find a contact, move a deal to a new stage, open a support ticket, or summarize an account — and if this server is running, it actually happens in the CRM. Nothing here is simulated: every tool makes a genuine HubSpot API call, with the same auth, error handling, and association logic a production integration needs.

Architecture

Claude never talks to HubSpot directly — every call is mediated, authenticated, and shaped by this server.

The server holds the only HubSpot credential (a private-app access token, read from an environment variable — never hard-coded or logged). Claude only ever sees the tool names, their typed inputs, and the formatted text results; it has no direct network access to HubSpot at all.

Setup

Five steps from clone to Claude calling real HubSpot tools. Full detail in the README.

  1. Install and build.
    npm install
npm run build
  2. Create a HubSpot private app in a free developer test account (preloaded with sample data) — Settings → Integrations → Private Apps, with contacts/deals/tickets read+write scopes.
  3. Set the token — copy .env.example to .env and paste it in.
  4. Point Claude at it via your MCP client config (Claude Desktop or Claude Code): 
    {
  "mcpServers": {
    "hubspot-crm": {
      "command": "node",
      "args": ["/absolute/path/to/dist/index.js"],
      "env": { "HUBSPOT_ACCESS_TOKEN": "your-token" }
    }
  }
}
  5. Or test it standalone with npm run inspector — opens the official MCP Inspector to call each tool directly, no Claude client required.

Tech stack & testing philosophy

Small, readable, and honest about its own limitations.

TypeScript @modelcontextprotocol/sdk Zod Vitest GitHub Actions CI

Every tool's business logic is a standalone exported function, separate from its MCP registration — so it's directly unit-testable without spinning up a protocol transport. All 26 tests run against a mocked fetch, so CI never needs a live HubSpot credential. The server was also verified end-to-end with a real MCP client connected over stdio, including a genuine HubSpot API authentication error round-tripping cleanly back through the protocol as a tool-level error rather than a crash.
